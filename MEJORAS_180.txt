  PARTE 1/3 — SCANNER (DETECCIÓN)                                       60 ítems
═══════════════════════════════════════════════════════════════════════════════

[ ]  1. ETW (Event Tracing for Windows) en tiempo real durante el scan para
        capturar ProcessStart, ImageLoad y FileIO de los últimos 30s aunque el
        proceso ya se haya cerrado antes de que el staff abra el scanner.

[ ]  2. Hash SHA-256 de cada $R presente en Recycle Bin contra base local de
        hashes conocidos de hacks (Vape, Liquid, Salhack, Inertia, Meteor,
        Wurst, Impact, Future, Sigma, Astolfo, Rise, Drip).

[ ]  3. Comparar timestamps $SI vs $FN del MFT — divergencia >5min indica
        timestamp tampering (técnica clásica de cheats para ocultarse).

[ ]  4. Parsear Amcache.hve (C:\Windows\AppCompat\Programs\Amcache.hve):
        historial de TODOS los .exe ejecutados en los últimos 30+ días, incluso
        si Prefetch fue limpiado.

[ ]  5. SRUM (System Resource Usage Monitor) — DB con uso de red/CPU/disco
        por proceso por hora. Detecta procesos que se borraron pero dejaron
        huella de tráfico.

[ ]  6. UserAssist en HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\
        UserAssist — programas ejecutados desde Explorer (rot13 decoded).

[ ]  7. ShimCache (AppCompatCache en SYSTEM hive) — registra programas que
        existieron incluso después del delete.

[ ]  8. BAM (Background Activity Moderator) y DAM — timestamps precisos de
        ejecución por SID en ControlSet001\Services\bam\State\UserSettings.

[ ]  9. JumpLists (AutomaticDestinations-ms y CustomDestinations-ms) —
        archivos abiertos recientemente por aplicación, sobreviven a wipes.

[ ] 10. Thumbcache (thumbcache_*.db) — miniaturas de imágenes y ejecutables
        ya borrados; algunas aún contienen metadatos del binario original.

[ ] 11. Lectura del USN Journal sin requerir admin vía DeviceIoControl
        directo con FSCTL_READ_USN_JOURNAL en handles read-only del volumen.

[ ] 12. Volume Shadow Copies (VSS) — escanear copias antiguas del filesystem
        para detectar evidencia ya borrada del estado actual.

[ ] 13. Detección de procesos con PEB unlinked (ocultos a Task Manager) usando
        NtQuerySystemInformation con SystemProcessInformation.

[ ] 14. Cross-check de procesos: WMI vs CreateToolhelp32Snapshot vs
        NtQuerySystemInformation. Mismatch en alguno = posible rootkit.

[ ] 15. Enumerar SetWindowsHookEx hooks activos y verificar firma de las DLLs
        que los implementan. Hook sin firma sobre todos los procesos = autoclicker.

[ ] 16. Detectar polling de GetAsyncKeyState desde proceso externo a javaw.exe
        (firma típica de killaura/aim-assist no inyectados).

[ ] 17. Análisis estático de cada .jar nuevo: descomprimir y buscar referencias
        a net.minecraft.client.Minecraft + patrones de obfuscation
        (pro-guard, allatori, transformers Mixin sospechosos).

[ ] 18. Hash de cada .jar contra Modrinth/CurseForge API de mods limpios para
        confirmar legitimidad antes de flaguearlo.

[ ] 19. Detectar Java agents en command line (-javaagent:): vector típico de
        Weave Loader, Vanilla+ Injector, JLoader.

[ ] 20. Inspeccionar JNI runtime: leer libpath de la JVM activa y listar
        DLLs cargadas en javaw.exe — DLLs sin firma o con nombre extraño = flag.

[ ] 21. Detectar drivers de kernel sin firma cargados (vulnerable drivers
        usados por DMA cheats: RTCore64.sys, dbutil_2_3.sys, gdrv.sys,
        AsrDrv101.sys, capcom.sys).

[ ] 22. Strings sweep en \\.\PhysicalMemory y firmware UEFI dumps en busca de
        signatures de hardware DMA cheats (PCILeech, CaptainDMA, EclipseDMA).

[ ] 23. Procesar logs de Sysmon si está instalado (Microsoft-Windows-Sysmon/
        Operational): Process Create, Image Load, Network Connect.

[ ] 24. Leer logs de Defender ASR rules
        (Microsoft-Windows-Windows Defender/Operational): Event ID 1121/1122
        registran ejecuciones bloqueadas previamente.

[ ] 25. Inspección de Defender Quarantine (C:\ProgramData\Microsoft\Windows
        Defender\Quarantine) — los hacks borrados por el AV quedan ahí.

[ ] 26. SmartScreen log (Microsoft-Windows-AppLocker/EXE and DLL y
        SmartScreen.evtx) — ejecutables bloqueados por reputación.

[ ] 27. AppLocker / WDAC blocked logs — empresa pro con políticas activas.

[ ] 28. Reglas custom del Firewall — un cheat suele agregarse a la whitelist.
        Listar reglas creadas por usuario en últimas 72h.

[ ] 29. Modificaciones recientes a hosts file (C:\Windows\System32\drivers\etc\
        hosts) — bypasses de licencias de cheat (vape.cc → 127.0.0.1).

[ ] 30. Detectar procesos huérfanos: PPID apunta a proceso ya muerto, pero el
        hijo sigue vivo con handles de javaw.exe abiertos.

[ ] 31. Detección de inyección DLL avanzada: SetWindowsHookEx,
        NtCreateThreadEx, QueueUserAPC, AtomBombing, Process Doppelgänging,
        Process Herpaderping, Process Ghosting.

[ ] 32. Enumerar handles abiertos a javaw.exe desde procesos no-relacionados
        (cheat externo escribiendo memoria de Minecraft via WriteProcessMemory).

[ ] 33. Detectar virtual joysticks (vJoy, ViGEm), macro recorders (ReWASD,
        X-Mouse Button Control con macros activas).

[ ] 34. Verificar Authenticode de TODOS los .exe en Prefetch — los cheats casi
        nunca firman; ratio firmados/no-firmados ejecutados es señal fuerte.

[ ] 35. Heurística de ratio: si el % de binarios sin firma ejecutados en la
        última hora supera el baseline del usuario, score++.

[ ] 36. Detectar tarjetas Wi-Fi/USB en modo monitor o promiscuo (señal de
        herramientas de packet capture/manipulation, raras en gaming).

[ ] 37. DNS cache reciente (Get-DnsClientCache) — lookups a dominios tipo
        vape.cc, azura.gg, moon-client.com, salhack.io, novoline.cc.

[ ] 38. Conexiones TCP/UDP recientes (Get-NetTCPConnection / netstat -ano)
        cruzadas con procesos: IPs/puertos sospechosos por proceso.

[ ] 39. Event ID 4688 (Process Creation) en Security log si auditing
        habilitado — cubre 7-90 días según política.

[ ] 40. Process Hollowing / Module Stomping detection: comparar memoria de
        sección .text mapeada vs imagen en disco para procesos sospechosos.

[ ] 41. Manifest tampering: validar que el digest declarado en el Authenticode
        coincida con el binario actual (defensa contra resigning).

[ ] 42. Bundle de YARA rules embebido (~150 reglas) para los hacks más comunes
        de Minecraft: Wurst, Meteor, Impact, Salhack, Inertia, Future, Sigma,
        Astolfo, Drip, Rise, Vape, Liquid, RusherHack, Ares.

[ ] 43. CAPA capabilities matrix sobre binarios sospechosos: anti-debug,
        anti-VM, persistence, code injection, network discovery.

[ ] 44. Time forensics: drift entre RTC, NTP y reloj de sistema. Drift >5min
        es señal de manipulación temporal (hacks que falsean timestamps).

[ ] 45. PowerShell history (ConsoleHost_history.txt en cada user) — comandos
        Invoke-WebRequest / iwr / curl a dominios de cheat.

[ ] 46. cmd doskey history y bash_history (si WSL está instalado).

[ ] 47. Logs de RDP, TeamViewer, AnyDesk, Parsec — terceros remotos durante el
        timeframe del scan (un amigo "ayudando" a hackear).

[ ] 48. SecurityHealthService logs: Defender disabled events, exclusions
        agregadas en últimas 72h.

[ ] 49. Service installations recientes (HKLM\System\CurrentControlSet\Services
        creadas en últimas 72h) — drivers de cheat se persisten así.

[ ] 50. Scheduled tasks creadas en últimas 24h con triggers OnLogon, OnIdle,
        AtStartup. Apuntan a binarios fuera de Program Files = sospechoso.

[ ] 51. Persistencia clásica: Startup folders (CurrentUser y AllUsers), Run/
        RunOnce keys, UserInitMprLogonScript, Winlogon\Userinit.

[ ] 52. WMI Event Subscriptions (root\subscription) — persistencia avanzada
        usada por hack loaders modernos.

[ ] 53. COM hijacking detection: enumerar CLSIDs en HKCU que sobrescriben
        HKLM (técnica de persistencia/loader).

[ ] 54. AppInit_DLLs, KnownDLLs, SafeBoot drivers, AlternateShell — vectores
        antiguos pero todavía explotados.

[ ] 55. Browser history sweep (Edge, Chrome, Firefox, Brave, Opera) últimas
        72h con keywords: "minecraft cheat", "killaura", nombres de hacks
        conocidos, tutoriales de bypass.

[ ] 56. Discord cache local: indexar archivos .jar/.zip recibidos en últimas
        72h (CachedImages, Code Cache contiene metadata de attachments).

[ ] 57. Telegram Desktop / WhatsApp Desktop downloads folders.

[ ] 58. Detectar overlays inyectados en javaw.exe: Steam, Epic, Battle.net
        Overlay (legítimo PERO también vector de hide para cheats).

[ ] 59. Sesiones activas: WinRM, SSH, VNC, AnyDesk durante el scan — alguien
        externo conectado mientras se hace el SS.

[ ] 60. Crash dumps recientes (.dmp en %localappdata%\CrashDumps y
        Windows\Minidump) — los cheats mal implementados crashean Minecraft;
        el dump apunta al módulo culpable.

  PARTE 2/3 — FILTRO (ANTI-FALSO POSITIVO)                              60 ítems
═══════════════════════════════════════════════════════════════════════════════

[ ]  1. Whitelist por SHA-256 de instaladores legítimos comunes:
        NVIDIA Experience, AMD Adrenalin, Intel ARC, Steam, Epic Games,
        Discord, Spotify, OBS Studio, Streamlabs.

[ ]  2. Whitelist por publisher Authenticode válido:
        NVIDIA Corp, AMD Inc, Microsoft, Mojang, Epic Games, Valve, Discord
        Inc → reduce score automáticamente sin importar otras señales.

[ ]  3. Distinguir "killaura" como nombre de archivo legítimo
        (skin pack llamado killaura.png o textura) vs ejecutable malicioso
        (.exe/.jar/.dll). Match estricto por extensión.

[ ]  4. Whitelist específica de mods legítimos de Minecraft Java:
        OptiFine, Sodium, Iris, Lithium, Phosphor, Starlight, Lunar Client,
        Badlion, Feather, Forge, Fabric, NeoForge, Quilt, Mod Menu, JEI/REI.

[ ]  5. Whitelist de launchers oficiales y third-party legítimos:
        Lunar Launcher, Badlion Client, Feather Client, ATLauncher, MultiMC,
        Prism Launcher, GDLauncher, MCLauncher, Modrinth App.

[ ]  6. Diferenciar CheatBreaker (deprecated) de Lunar Client (sucesor) —
        son el mismo binario renombrado, no doble flag.

[ ]  7. Reputación por path: archivos en C:\Program Files\WindowsApps\,
        C:\Windows\System32\, C:\Windows\SysWOW64\, C:\Windows\WinSxS\
        → probabilidad de hack casi nula.

[ ]  8. Pre-cachear hashes de DLLs comunes de C:\Windows\System32 al inicio
        del scan; si aparece como sospechosa pero el hash matchea, descartar.

[ ]  9. Edad del archivo > 1 año + sin modificación reciente = baja
        probabilidad de hack (los hacks rotan rápido, las versiones viven días).

[ ] 10. Detectar patrones "test", "prueba", "demo", "ejemplo" en filename
        + extensión inocua (.txt, .docx) → no flag.

[ ] 11. Aprendizaje incremental por feedback: si staff marca un FP, guardar
        (filename_pattern, extension, parent_hash) y aplicar en futuros scans
        de la misma empresa.

[ ] 12. Consenso global: si un hash aparece en >50 scans de >10 empresas
        sin haber sido nunca marcado como cheat → auto-whitelist global.

[ ] 13. Whitelist Discord: Discord_Overlay.exe, DiscordPTB, DiscordCanary,
        BetterDiscord, Vencord (estas dos últimas son mods de Discord client
        que hookean pero no son cheat de Minecraft).

[ ] 14. Whitelist periféricos:
        Razer Cortex/Synapse, Logitech G HUB/GHUB, Corsair iCue,
        SteelSeries Engine, HyperX NGenuity, EVGA Precision X1.

[ ] 15. Whitelist macros legales de gamepad/teclado (cuando estén firmadas
        por su vendor): JoyToKey, Xpadder, Antimicro firmado.

[ ] 16. AutoHotkey: scripts firmados con cert del usuario o cuyo contenido
        no toca processes externos → no flag por extensión .ahk.

[ ] 17. OBS Studio + plugins (.dll loaders): OBS hace hooks de captura de
        ventana que se parecen a inyectores. Whitelist OBS y sus plugins
        firmados.

[ ] 18. ReShade / SpecialK / SweetFX: overlays gráficos. FP en VAC pero no
        cheat de Minecraft. Whitelist.

[ ] 19. MSI Afterburner / RivaTuner Statistics Server (RTSS) — overlay con
        DLL injection legítimo. Whitelist por publisher.

[ ] 20. Procesos antivirus en background:
        Avast, Kaspersky, Bitdefender, Norton, McAfee, ESET, Sophos, Malware-
        bytes — sus binarios inyectan en otros procesos, es legítimo.

[ ] 21. Microsoft Defender (MsMpEng.exe, NisSrv.exe, SecurityHealthService) —
        whitelist absoluta, son SO esencial.

[ ] 22. Filtrar binarios en %WINDIR%\WinSxS, %ProgramFiles%\Common Files\
        Microsoft Shared, %SystemRoot%\Servicing, %WINDIR%\assembly.

[ ] 23. Lista de paquetes UWP/MSIX firmados por Microsoft Store
        (HKLM\Software\Classes\Local Settings\Software\Microsoft\Windows\
        CurrentVersion\AppModel) → trust automático.

[ ] 24. Validar cadena completa de certificados Authenticode (no solo
        "tiene firma"). Cert revocado o cadena rota = flag.

[ ] 25. Blacklist de certs robados/revocados conocidos (CRL públicas
        + DigiCert/Sectigo revocation lists para los últimos 12 meses).

[ ] 26. Si el .exe está firmado pero el subject CN está en lista negra
        (ej. "Beijing Kunlun Tech", o publishers de mineros conocidos)
        → score++ aunque la firma sea válida.

[ ] 27. Bayesian filter sobre filename: tokens como "loader", "injector",
        "client" + Minecraft-related → score++; tokens como "setup",
        "installer", "update", "uninstaller" → score--.

[ ] 28. Filtro por idioma del SO: en es-AR/es-MX/es-ES ciertos paths cambian
        (Mis Documentos vs My Documents). Adaptar reglas.

[ ] 29. Filtro contextual TLauncher: en zonas de bajo poder adquisitivo,
        TLauncher es FP recurrente. Marcar como advisory pero no banear.

[ ] 30. Filtrar el screenshotter del propio Argus para no detectarse a sí
        mismo (ArgusScanner.exe, MinecraftSSTool.exe, sus hijos PowerShell).

[ ] 31. Filtros custom por empresa: cada cliente puede sumar paths/hashes
        a su whitelist privada (ej. herramientas internas de admin).

[ ] 32. Filtro de prefetch inteligente: si el .pf existe pero el .exe original
        sigue presente con firma válida y en Program Files, no flag.

[ ] 33. Excluir archivos en ruta de OneDrive sincronizado para reducir noise
        de cosas del trabajo / personales del staff.

[ ] 34. Excluir mods en folder de instancias de TLauncher/Lunar/Badlion
        cuando el .jar tiene hash conocido en Modrinth/CurseForge.

[ ] 35. Excluir cache de modpacks de CurseForge (%appdata%\.minecraft\mods
        y descargas oficiales) si el hash matchea el manifest del modpack.

[ ] 36. Excluir archivos del Recycle Bin que provienen de procesos de
        actualización (filename con sufijos "old", "backup", "_v1", "~tmp").

[ ] 37. Diferenciar ".rise" como extensión de archivo (raro) vs ".rise"
        como folder (Rise client config folder). Solo flagear .rise si es ext.

[ ] 38. Smart match en hack_terms: solo flag si el término es palabra
        completa (regex \bvertex\b), no substring. Evita FP en
        "vertexshader.frag", "matrix-multiply.bat", etc.

[ ] 39. Filtro contextual temporal: si un .exe sospechoso fue ejecutado AL
        MISMO TIEMPO que javaw.exe → score++. Si fue ejecutado el día
        anterior y nunca más → score--.

[ ] 40. Filtro de red: si el archivo abre conexiones SOLO a 192.168.x.x,
        10.x.x.x, 127.0.0.1 → tool de LAN/dev, baja sospecha.

[ ] 41. Filtro de tamaño: hacks típicos pesan entre 1-50 MB (.exe) o
        100 KB-5 MB (.jar). Fuera de estos rangos, score--.

[ ] 42. Heurística "primera vez visto" segura: si el hash NUNCA fue visto
        en la base global de Argus, NO banear automáticamente — marcar para
        revisión humana primero (evita ser zero-day-paranoid).

[ ] 43. Threshold dinámico de risk score por empresa: cliente premium
        configura "estricto/normal/permisivo" según política del server.

[ ] 44. Modo "torneo" más estricto vs modo "casual" más permisivo:
        threshold y peso de heurísticas distinto por flag del scan.

[ ] 45. Excluir paths de recovery de Windows: C:\Recovery, C:\$WINDOWS.~BT,
        C:\$WINDOWS.~WS, C:\$Windows.~Q, C:\PerfLogs.

[ ] 46. Detectar si el host es Windows Server y bajar peso de heurísticas
        que asumen entorno desktop (un staff puede correr el scanner desde
        un VPS).

[ ] 47. Excluir archivos que son parte de una Steam Workshop subscription
        (filename matching con manifests de %steam%\steamapps\workshop).

[ ] 48. Excluir game pass / Xbox UWP titles
        (C:\Program Files\WindowsApps\<package>) — están firmados por MS.

[ ] 49. Mejor parser de USN Journal: ignorar transactions de Windows Update
        (TrustedInstaller, wuauclt) y System Restore.

[ ] 50. Mejor parser de Prefetch: ignorar PF files de Microsoft Edge,
        Defender, Windows Search Indexer (basura común que no aporta).

[ ] 51. Filtrar entradas de scan_file_activity_log que sean del propio
        Argus (su propio log, screenshot, json output, dist/ArgusScanner.exe).

[ ] 52. Detectar reinstalaciones legítimas: mismo binario, mismo hash, ruta
        canonical, intervalo razonable → no doble flag.

[ ] 53. Detectar mod updaters (CurseForge launcher, Modrinth app) que
        copian/borran .jar como parte de updates → no FP de "ráfaga de
        borrado masivo".

[ ] 54. Confianza modulada por antigüedad y reputación del staff: staff con
        >100 veredictos correctos tiene más peso al marcar FP.

[ ] 55. Confidence ensemble con factor humano:
        AI_score + heuristic_score + historical_feedback → score consolidado
        ponderado en lugar de simple OR.

[ ] 56. Filtrar logs/screenshots de software de soporte legítimo:
        TeamViewer en sesiones del propio staff (no en ajenas), AnyDesk
        autorizado por la empresa.

[ ] 57. Detectar tools de desarrollo legítimas: Visual Studio Code, Cursor,
        IntelliJ, NetBeans, Sublime — no flag aunque parezcan inyectores.

[ ] 58. Filtro de Java agents legítimos: profilers (YourKit, JProfiler,
        VisualVM), debuggers, build tools (Gradle agents).

[ ] 59. Excluir archivos creados/modificados durante updates conocidos
        de Windows (cruzando timestamps con WindowsUpdate.log).

[ ] 60. "Penalty cooldown": si una empresa ya marcó X hashes como FP en las
        últimas 48h, subir threshold dinámicamente para esa empresa hasta
        que se ajusten heurísticas — evita lluvia de FPs idénticos.

El scanner actual es Windows-only por diseño: depende de winreg, ctypes.windll,
$RECYCLE.BIN, Prefetch, USN Journal, Amcache, etc. Llevarlo a Linux NO es
recompilar — requiere refactor en módulos por plataforma y reemplazar las
fuentes de evidencia. Esta sección agrupa el trabajo necesario para una
variante "ArgusScanner Linux" (jugadores de Minecraft Java en escritorio
Linux: Arch, Ubuntu, Fedora, etc.).

[ ]  1. Refactor del proyecto a estructura por plataforma:
        source/scanner_core/        (lógica común: hashes, hack-names, upload)
        source/scanner_windows/     (winreg, prefetch, recycle, usn, amcache)
        source/scanner_linux/       (proc, journal, trash, dotfiles, lsof)
        Inyectar el backend correcto según sys.platform en runtime.

[ ]  2. Aislar TODOS los `import winreg` y `import ctypes.wintypes` detrás de
        un wrapper `platform_api` con stubs no-op para Linux/Mac.

[ ]  3. Equivalente Linux de la papelera: parsear
        `~/.local/share/Trash/info/*.trashinfo` (estándar XDG) + cruzar con
        `~/.local/share/Trash/files/`. Reemplaza el parser de $RECYCLE.BIN.

[ ]  4. Equivalente Linux de Prefetch / "ejecutados":

          - shell-snapshots de fish (~/.local/share/fish/fish_history)
          - timestamps de acceso (atime) de binarios en ~/.local/bin, ~/.cache.
