# Privacy by Design Checklist (Pre-merge)

1. [ ] propósito del procesamiento definido.
2. [ ] base legal documentada.
3. [ ] minimización de datos aplicada.
4. [ ] sólo campos estrictamente necesarios.
5. [ ] clasificación de sensibilidad asignada.
6. [ ] retención definida por campo.
7. [ ] plan de borrado/anonimización implementado.
8. [ ] transferencia internacional evaluada.
9. [ ] subprocesadores identificados.
10. [ ] DPA aplicable revisado.
11. [ ] consentimiento requerido evaluado.
12. [ ] UX de consentimiento clara (si aplica).
13. [ ] seguridad en tránsito (TLS) validada.
14. [ ] seguridad en reposo definida.
15. [ ] secretos fuera de código fuente.
16. [ ] logging sin PII excesiva.
17. [ ] redacción de campos sensibles en logs.
18. [ ] acceso por rol mínimo (RBAC).
19. [ ] endpoint authz revisado.
20. [ ] CSRF/rate-limit aplicado según riesgo.
21. [ ] protección anti-replay para APIs M2M.
22. [ ] auditoría de acceso habilitada.
23. [ ] endpoint DSAR afectado actualizado.
24. [ ] export de datos soportado.
25. [ ] right-to-be-forgotten contemplado.
26. [ ] pruebas de seguridad agregadas.
27. [ ] threat model actualizado.
28. [ ] documentación de privacidad actualizada.
29. [ ] owner de datos definido.
30. [ ] checklist firmado en PR antes de merge.
